1. 插件生命流程：校验用户配置 -> 创建实例（轻量化，不分配资源，构造和初始化分开）->初始化资源 -> 调用插件 -> 释放资源

   1. 问题：

      1. 调用方需要将初始化函数放在try内，防止初始化错误；shutdown函数应该支持“初始化一半后报错”的释放资源；
      2. 将上述try块集成为一个函数，runtime直接调用`with managed_plugin(descriptor, validated_config) as plugin:`
      3. initialize函数应该传什么参数？

      - 选择一：直接传Config类
      - 选择二：写一个PluginContext，Config作为其中的属性，统一传PluginContext。优点：如果插件还需要 Runtime 提供的信息或服务，后续方便拓展；可以区分插件配置与运行信息  eg.某training插件需要写入日志，日志由Runtime配置，插件的Config类无权干涉，这时需要PluginContext

      4. Runtime如何确保插件factory类返回实例具备initialize和shutdown方法？
      提供一份统一的PluginLifeCycle，明确告诉开发者插件需要实现initialize和shutdown，但只能检查有没有实现这两个函数，不会检查函数的具体行为。同时，直接检查实例有无initialize方法也是合理方案，但易于插件开发者统一规范

      5. 记录关闭失败：将shutdown再嵌套在一个try块内，同时使用logger记录原因
